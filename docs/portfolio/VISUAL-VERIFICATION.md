# Visual Verification

Do not judge the portfolio from code alone.

Where browser/preview capability exists:

Run
→ Open rendered experience
→ Inspect
→ Capture
→ Critique
→ Fix
→ Reload
→ Repeat

## Mandatory review states

1. Arrival
2. Walter introduction
3. VoiceOps
4. PropControl
5. VisionOps Capture
6. VisionOps Findings

12. Contact

## For every major frame ask

- Is there a clear focal point?
- Does this look like a designed world?
- Does it still feel like a webpage?
- Does the property feel physical?
- Does the AI layer feel distinct?
- Is the camera cinematic?
- Is there enough depth?
- Is there useful foreground/background?
- Is lighting guiding attention?
- Are there unnecessary cards or HUD panels?
- Would this frame look strong as an award-site case-study screenshot?

If not, improve it.

## Browser/runtime checks

Where possible inspect:
- WebGL warnings
- shader errors
- missing assets / 404s
- GSAP errors
- scroll desynchronization
- resize problems
- mobile overflow
- incorrect chapter activation
- broken external product links
- missing resume/contact destinations

## Honesty rule

Do not claim graphical verification if the environment could not actually render or visually inspect the site.
